Windows startup audit

SystemCompass

SystemCompass inventories the startup mechanisms Windows actually exposes - Run and RunOnce keys, Startup folders, scheduled tasks, automatic services and Winlogon hooks - then explains each entry by category, risk, signer and recovery advice.

  • Audit first. The default run only collects and classifies. Changes are explicit, use supported Windows facilities and never delete Run values.
  • Verified changes. Every toggle is re-read from the registry, service manager or task scheduler. A failed read-back is reported as failed.
  • Journal and rollback. An append-only JSONL journal records the before and after state; verified changes can be rolled back.
  • Protected entries. Windows security components, driver services and remote-access tooling are matched by signature and path and cannot be toggled.
  • Curated tweaks. 64 evidence-labelled definitions with risk levels, captured previous values and a deny-list for security-reducing settings.
  • Local by design. No network code, no telemetry. Markdown and JSON exports redact user names, machine names, SIDs and personal paths.

MCP over SSH

claude-code-bridge

Let one coding-agent session message another machine's session over SSH. No cloud relay, no shared account.

View on GitHub Quickstart

How it works

The server runs locally as an MCP process. When you send a message, it runs ssh <peer> <command> -p --resume <session-id> and pipes the message to stdin. The remote session's stdout is the reply.

Session ids are stored per peer in a small state file. If the remote conversation is provably gone, the bridge retries once with a fresh session. A network error never resets the stored history.

agent (host)  >  stdio  >  cc_peer.py  >  ssh  >  agent -p (remote)

Features

Resumable conversations

The remote session continues across calls. Only a provably stale session is replaced.

Safe retries

Timeouts and unreachable hosts are returned as errors without touching the stored session.

sh and cmd peers

Correct quoting for POSIX and Windows peers. SSH binary fallbacks for common Windows installs.

Single file, no dependencies

Python standard library only. The self-test runs with a single command.

Quickstart

Requires Python 3.11+, the same agent CLI on both machines, and SSH key auth to the peer.

Install it, or run it directly with uvx:

$ pipx install claude-code-bridge-mcp==1.0.0
# or
$ uvx --from claude-code-bridge-mcp==1.0.0 cc-peer

Create ~/.cc-peer.json:

{
  "peers": {
    "my-server": {
      "ssh": "my-server",
      "shell": "sh",
      "cwd": "",
      "command": "agent",
      "args": [],
      "ssh_args": ["-o", "BatchMode=yes", "-o", "ConnectTimeout=10"],
      "timeout": 600
    }
  }
}

Register the server with your MCP client:

{
  "mcpServers": {
    "cc-peer": {
      "command": "uvx",
      "args": ["--from", "claude-code-bridge-mcp==1.0.0", "cc-peer"]
    }
  }
}

Then call list_peers() and send_message(peer="my-server", message="...").

Safety notes

  • Authenticate with SSH keys and BatchMode=yes. The bridge never handles passwords and stores no secrets.
  • Everything you send becomes input to the remote session. Do not pass credentials through it.
  • The bridge adds no permission-bypass flags on its own.
